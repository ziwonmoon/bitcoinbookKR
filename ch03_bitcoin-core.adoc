== 비트코인 코어: 참조 구현

사람들이 자기 값진 재화와 서비스를 내주고 돈을 받는 것은, 나중에 그 돈을 쓸 수
있으리라 믿기 때문입니다. 위조되었거나 예기치 않게 가치가 떨어진 돈은 나중에 쓰지
못할 수 있으므로, 비트코인을 받는 사람이라면 누구나 자신이 받는 비트코인의 무결성을
검증할 강한 유인이 있습니다. 비트코인 시스템은 여러분의 로컬 컴퓨터에서만 돌아가는
소프트웨어로도 위조와 가치 하락을 비롯한 몇 가지 결정적인 문제를 완벽히 막을 수
있도록 설계되었습니다. 그런 기능을 제공하는 소프트웨어를 _완전 검증 노드_ 라고
하는데, 확인된 모든 비트코인 트랜잭션을 시스템의 모든 규칙에 비추어 검증하기
때문입니다. 완전 검증 노드는 ((("full nodes")))줄여서 _풀 노드_ 라고 하며, 비트코인이 어떻게
작동하고 네트워크에서 지금 무슨 일이 일어나고 있는지 이해하는 데 필요한 도구와
데이터도 제공할 수 있습니다.

이 장에서는 비트코인 네트워크 초창기부터 대부분의 풀 노드 운영자가 써온 구현인
비트코인 코어를 설치합니다. 그런 다음 여러분의 노드에서 블록과 트랜잭션을 비롯한
데이터를 살펴봅니다. 이 데이터가 권위 있는 이유는 어떤 강력한 주체가 그렇게 지정해
주어서가 아니라, 여러분의 노드가 독립적으로 검증했기 때문입니다. 이 책의 나머지
부분에서도 비트코인 코어를 계속 사용해 블록체인 및 네트워크와 관련된 데이터를
만들고 살펴보겠습니다.

=== 비트코인에서 비트코인 코어로

비트코인은 ((("Bitcoin Core", "explained", id="bitcoin-core-explain")))_오픈소스_ 프로젝트이며, 소스 코드는 개방형(MIT)
라이선스로 공개되어 있어 어떤 목적으로든 무료로 내려받아 쓸 수 있습니다. 오픈소스일
뿐 아니라 비트코인은 자원봉사자들의 열린 커뮤니티가 개발합니다. 처음에 그 커뮤니티는
((("Nakamoto, Satoshi")))사토시 나카모토 한 사람뿐이었습니다. 2023년에 이르러 비트코인 소스
코드의 기여자는 1,000명이 넘었고, 그중 열두어 명은 거의 전업으로, 수십 명은 시간제로
코드를 작업하고 있습니다. 누구나 코드에 기여할 수 있습니다&#x2014;여러분도요!

사토시 나카모토가 비트코인을 만들었을 때, 소프트웨어는 백서(<<satoshi_whitepaper>>에
수록)가 발표되기 전에 거의 완성되어 있었습니다. 사토시는 그것에 관한 논문을 내기 전에
구현이 실제로 작동하는지 확인하고 싶어 했습니다. 그냥 "Bitcoin"이라고 불리던 그 첫
구현은 이후 크게 수정되고 개선되었습니다. 그리고 다른 구현들과 구별하기 위해 _비트코인
코어_ 라고 불리는 것으로 발전했습니다. 비트코인 코어는 비트코인 시스템의 _참조 구현_
이며, 이는 기술의 각 부분을 어떻게 구현해야 하는지에 대한 기준을 제공한다는 뜻입니다.
비트코인 코어는 지갑, 트랜잭션 및 블록 검증 엔진, 블록 구성 도구, 그리고 비트코인 P2P
통신의 모든 현대적 요소를 포함해 비트코인의 모든 측면을 구현합니다.

<<bitcoin_core_architecture>>에 비트코인 코어의 아키텍처를 나타냈습니다.

비트코인 코어가 시스템의 여러 주요 부분에 대한 참조 구현 역할을 하지만, 비트코인
백서도 시스템의 초기 요소 몇 가지를 설명합니다. 2011년 이후 시스템의 주요 부분은
대부분 https://oreil.ly/BCXAQ[비트코인 개선 제안(BIP)] 모음에 문서화되었습니다. 이
책 전반에서는 ((("BIPs (Bitcoin Improvement Proposals)")))((("Bitcoin Improvement Proposals", see="BIPs")))BIP 규격을 번호로 지칭합니다. 예를 들어 BIP9는 비트코인의
여러 주요 업그레이드에 쓰인 방식을((("Bitcoin Core", "explained", startref="bitcoin-core-explain"))) 설명합니다.

=== 비트코인 개발 환경

여러분이 개발자라면 비트코인 애플리케이션을 작성하는 데 필요한 도구와 라이브러리,
지원 소프트웨어를 갖춘 개발 환경을 마련하고 싶을 것입니다. 이 장은 기술적인 내용이
많은데, 그 과정을 단계별로 짚어 보겠습니다. 내용이 너무 빽빽하게 느껴진다면(그리고
실제로 개발 환경을 구축하는 것이 아니라면) 덜 기술적인 다음 장으로 건너뛰어도
좋습니다.

=== 소스 코드에서 비트코인 코어 컴파일하기

비트코인 코어의
소스 코드는((("Bitcoin Core", "compiling from source code", id="bitcoin-core-compile")))((("compiling Bitcoin Core from source code", id="compile-bitcoin-core")))((("source code, compiling Bitcoin Core", id="source-code-compile"))) 압축 파일로 내려받거나 깃허브에서 소스 저장소를 클론해
가져올 수 있습니다. https://oreil.ly/hN9g1[비트코인 코어 다운로드 페이지]에서 가장
최근 버전을 골라 소스 코드 압축 파일을 내려받으세요. 아니면 Git 명령줄로
https://oreil.ly/BdOwl[깃허브 비트코인 페이지]에서 소스 코드의 로컬 사본을 만들 수도
있습니다.

[TIP]
====
이 장의 여러 예제에서는 "터미널" 애플리케이션으로 접근하는 운영체제의 명령줄
인터페이스("셸"이라고도 합니다)를 사용합니다. 셸은 프롬프트를 표시하고, 여러분이
명령을 입력하면 셸이 어떤 텍스트와 함께 다음 명령을 위한 새 프롬프트로 응답합니다.
프롬프트는 시스템마다 다르게 보일 수 있지만, 아래 예제에서는 +$+ 기호로 나타냅니다.
예제에서 +$+ 기호 뒤의 텍스트를 볼 때 +$+ 기호는 입력하지 말고 바로 뒤에 오는 명령만
입력한 다음 엔터를 눌러 실행하세요. 예제에서 각 명령 아래의 줄들은 그 명령에 대한
운영체제의 응답입니다. 다음 +$+ 접두사가 보이면 새 명령이라는 뜻이니 같은 과정을
반복하면 됩니다.
====

여기서는 +git+ 명령으로 소스 코드의 로컬 사본("클론")을 만듭니다.

----
$ git clone https://github.com/bitcoin/bitcoin.git
Cloning into 'bitcoin'...
remote: Enumerating objects: 245912, done.
remote: Counting objects: 100% (3/3), done.
remote: Compressing objects: 100% (2/2), done.
remote: Total 245912 (delta 1), reused 2 (delta 1), pack-reused 245909
Receiving objects: 100% (245912/245912), 217.74 MiB | 13.05 MiB/s, done.
Resolving deltas: 100% (175649/175649), done.
----

[TIP]
====
Git은 가장 널리 쓰이는 분산 버전 관리 시스템으로, 소프트웨어 개발자의 도구 상자에
빠질 수 없는 요소입니다. 아직 없다면 운영체제에 +git+ 명령이나 Git용 그래픽 사용자
인터페이스를 설치해야 할 수 있습니다.
====

Git 클론 작업이 끝나면 _bitcoin_ 디렉터리에 소스 코드 저장소의 완전한 로컬 사본이
생깁니다. +cd+ 명령으로 이 디렉터리로 이동하세요.

----
$ cd bitcoin
----
==== 비트코인 코어 릴리스 고르기

기본적으로((("Bitcoin Core", "compiling from source code", "selecting release version", id="bitcoin-core-compile-release")))((("compiling Bitcoin Core from source code", "selecting release version", id="compile-bitcoin-core-release")))((("source code, compiling Bitcoin Core", "selecting release version", id="source-code-compile-release")))((("release version (Bitcoin Core), selecting", id="release-select")))((("selecting", "release version (Bitcoin Core)", id="select-release"))) 로컬 사본은 가장 최근 코드와 동기화되는데, 이는 불안정
버전이거나 비트코인의 베타 버전일 수 있습니다. 코드를 컴파일하기 전에 릴리스 _태그_
를 체크아웃해 특정 버전을 고르세요. 그러면 로컬 사본이 키워드 태그로 식별되는 코드
저장소의 특정 스냅숏과 동기화됩니다. 태그는 개발자들이 코드의 특정 릴리스를 버전
번호로 표시하는 데 씁니다. 먼저 사용할 수 있는 태그를 찾기 위해 +git tag+ 명령을
사용합니다.

----
$ git tag
v0.1.5
v0.1.6test1
v0.10.0
...
v0.11.2
v0.11.2rc1
v0.12.0rc1
v0.12.0rc2
...
----

태그 목록은 비트코인의 모든 릴리스 버전을 보여줍니다. 관례적으로 테스트용인
((("release candidates")))_릴리스 후보_ 에는 접미사 "rc"가 붙습니다. 운영 시스템에서 돌릴 수
있는 안정 릴리스에는 접미사가 없습니다. 앞의 목록에서 가장 높은 버전의 릴리스를
고르는데, 이 글을 쓰는 시점에는 v24.0.1이었습니다. 로컬 코드를 이 버전과 동기화하려면
+git checkout+ 명령을 사용합니다.

----
$ git checkout v24.0.1
Note: switching to 'v24.0.1'.

You are in 'detached HEAD' state. You can look around, make experimental
changes and commit them, and you can discard any commits you make in this
state without impacting any branches by switching back to a branch.

HEAD is now at b3f866a8d Merge bitcoin/bitcoin#26647: 24.0.1 final changes
----

+git status+ 명령을 실행하면 원하는 버전이 "체크아웃"되었는지((("Bitcoin Core", "compiling from source code", "selecting release version", startref="bitcoin-core-compile-release")))((("compiling Bitcoin Core from source code", "selecting release version", startref="compile-bitcoin-core-release")))((("source code, compiling Bitcoin Core", "selecting release version", startref="source-code-compile-release")))((("release version (Bitcoin Core), selecting", startref="release-select")))((("selecting", "release version (Bitcoin Core)", startref="select-release"))) 확인할 수
있습니다.

----
HEAD detached at v24.0.1
nothing to commit, working tree clean
----

==== 비트코인 코어 빌드 설정하기

((("Bitcoin Core", "compiling from source code", "configuring build", id="bitcoin-core-compile-configure")))((("compiling Bitcoin Core from source code", "configuring build", id="compile-bitcoin-core-configure")))((("source code, compiling Bitcoin Core", "configuring build", id="source-code-compile-configure")))((("configuring", "Bitcoin Core build", id="configure-build")))소스 코드에는 여러 파일에 걸쳐 문서가 들어 있습니다. _bitcoin_
디렉터리의 _README.md_ 에 있는 주 문서를 살펴보세요. 이 장에서는 리눅스(유닉스 계열
시스템)에서 +bitcoind+ 라고 부르는 비트코인 코어 데몬(서버)을 빌드합니다.
_doc/build-unix.md_ 를 읽고 여러분의 플랫폼에서 +bitcoind+ 명령줄 클라이언트를
컴파일하는 방법을 확인하세요. 다른 방법은 _doc_ 디렉터리에서 찾을 수 있습니다.
예를 들어 윈도우용 안내는 _build-windows.md_ 에 있습니다. 이 글을 쓰는 시점에는
안드로이드, FreeBSD, NetBSD, OpenBSD, macOS(OSX), 유닉스, 윈도우용 안내가 제공됩니다.

빌드 문서의 앞부분에 있는 빌드 선행 조건을 꼼꼼히 살펴보세요. 비트코인 컴파일을
시작하기 전에 시스템에 반드시 있어야 하는 라이브러리들입니다. 이 선행 조건이 빠져
있으면 빌드 과정이 오류와 함께 실패합니다. 선행 조건을 놓쳐서 그런 일이 생겼다면, 그
라이브러리를 설치한 뒤 멈춘 지점부터 빌드를 이어갈 수 있습니다. 선행 조건이 설치되어
있다고 보고, _autogen.sh_ 스크립트로 빌드 스크립트 모음을 생성하는 것으로 빌드 과정을
시작합니다.

----
$ ./autogen.sh
libtoolize: putting auxiliary files in AC_CONFIG_AUX_DIR, 'build-aux'.
libtoolize: copying file 'build-aux/ltmain.sh'
libtoolize: putting macros in AC_CONFIG_MACRO_DIRS, 'build-aux/m4'.
 ...
configure.ac:58: installing 'build-aux/missing'
src/Makefile.am: installing 'build-aux/depcomp'
parallel-tests: installing 'build-aux/test-driver'
----

_autogen.sh_ 스크립트는 자동 설정 스크립트 모음을 만듭니다. 이 스크립트들은 여러분의
시스템을 조사해 올바른 설정을 찾아내고, 코드를 컴파일하는 데 필요한 라이브러리가 모두
있는지 확인합니다. 그중 가장 중요한 것이 +configure+ 스크립트인데, 빌드 과정을 맞춤
설정할 수 있는 여러 옵션을 제공합니다. +--help+ 플래그로 다양한 옵션을 볼 수 있습니다.

----
$ ./configure --help
`configure' configures Bitcoin Core 24.0.1 to adapt to many kinds of systems.

Usage: ./configure [OPTION]... [VAR=VALUE]...

...
Optional Features:
  --disable-option-checking  ignore unrecognized --enable/--with options
  --disable-FEATURE       do not include FEATURE (same as --enable-FEATURE=no)
  --enable-FEATURE[=ARG]  include FEATURE [ARG=yes]
  --enable-silent-rules   less verbose build output (undo: "make V=1")
  --disable-silent-rules  verbose build output (undo: "make V=0")
...
----

+configure+ 스크립트는 +--enable-FEATURE+ 와 +--disable-FEATURE+ 플래그로
+bitcoind+ 의 특정 기능을 켜거나 끌 수 있게 해줍니다. 여기서 pass:[<span
class="keep-together"><code>FEATURE</code></span>] 자리에는 도움말 출력에 나열된 기능
이름이 들어갑니다. 이 장에서는 기본 기능을 모두 켠 채로 +bitcoind+ 클라이언트를
빌드합니다. 설정 플래그를 쓰지는 않겠지만, 클라이언트에 어떤 선택 기능이 있는지
이해하기 위해 한번 살펴보시기를 권합니다. 학교 환경이라면 컴퓨터실 제약 때문에
홈 디렉터리에 애플리케이션을 설치해야 할 수도 있습니다(예: +--prefix=$HOME+ 사용).

다음은 +configure+ 스크립트의 기본 동작을 바꾸는 유용한 옵션 몇 가지입니다.

++++
<dl>
<dt><code>--prefix=$HOME</code></dt>
<dd><p>결과 실행 파일의 기본 설치 위치(<em>/usr/local/</em>)를 덮어씁니다. 모든 것을 홈 디렉터리에 두려면 <code>$HOME</code> 을, 또는 다른 경로를 쓰세요.</p></dd>

<dt><code>--disable-wallet</code></dt>
<dd><p>참조 지갑 구현을 끕니다.</p></dd>

<dt><code>--with-incompatible-bdb</code></dt>
<dd><p>지갑을 빌드하는 경우, 호환되지 않는 버전의 Berkeley DB 라이브러리 사용을 허용합니다.</p></dd>

<dt><code>--with-gui=no</code></dt>

=== 비트코인 코어 노드 실행하기

비트코인의 ((("Bitcoin Core", "nodes", "running", id="bitcoin-core-nodes-running")))((("nodes", "running", id="nodes-running")))((("running nodes", id="running-nodes")))P2P 네트워크는 네트워크 "노드"들로 이루어지는데, 대부분 개인이
운영하고 일부는 비트코인 서비스를 제공하는 사업자가 운영합니다. 비트코인 노드를
운영하는 사람은 비트코인 블록체인을 직접적이고 권위 있게 볼 수 있으며, 자기 시스템이
독립적으로 검증한, 쓸 수 있는 모든 비트코인의 로컬 사본을 갖게 됩니다. 노드를 운영하면
트랜잭션을 검증하는 데 제삼자에게 의존할 필요가 없습니다. 게다가 비트코인 노드로
여러분의 지갑이 받는 트랜잭션을 온전히 검증하면 비트코인 네트워크에 기여하고 그것을
더 견고하게 만드는 데 보탬이 됩니다.

다만 노드를 운영하려면 처음에 500GB가 넘는 데이터를 내려받아 처리해야 하고, 이후에도
하루에 약 400MB의 비트코인 트랜잭션을 처리해야 합니다. 이 수치는 2023년 기준이며
시간이 지나면서 늘어날 가능성이 높습니다. 노드를 끄거나 며칠 동안 인터넷 연결이
끊기면, 노드는 놓친 데이터를 내려받아야 합니다. 예를 들어 비트코인 코어를 10일 동안
꺼두었다면 다음에 실행할 때 약 4GB를 내려받아야 합니다.

모든 트랜잭션을 인덱싱하고 블록체인 전체 사본을 보관할지에 따라 디스크 공간도 많이
필요할 수 있습니다. 비트코인 코어를 몇 년 동안 운영할 계획이라면 최소 1TB는 있어야
합니다. 기본적으로 비트코인 노드는 트랜잭션과 블록을 다른 노드("피어"라고 합니다)에
전송하기도 하므로 업로드 인터넷 대역폭을 소비합니다. 인터넷 연결이 제한적이거나 데이터
상한이 낮거나 종량제(기가비트 단위 과금)라면 그 회선에서는 비트코인 노드를 운영하지
않는 편이 좋고, 운영하더라도 대역폭을 제한하는 방식으로 하세요
(<<bitcoincorenode_config>> 참고). 대신 https://oreil.ly/cIwf3[Blockstream Satellite]
같은 무료 위성 데이터 제공자처럼 다른 네트워크에 노드를 연결할 수도 있습니다.

[TIP]
====
비트코인 코어는 기본적으로 블록체인의 전체 사본을 보관하며, 2009년 시작 이후 비트코인
네트워크에서 확인된 거의 모든 트랜잭션이 여기 들어 있습니다. 이 데이터셋은 수백
기가바이트 크기이며, CPU와 인터넷 연결 속도에 따라 몇 시간에서 며칠에 걸쳐 조금씩
내려받습니다. 블록체인 데이터셋 전체를 내려받기 전까지 비트코인 코어는 트랜잭션을
처리하거나 잔액을 갱신할 수 없습니다. 최초 동기화를 마칠 만큼 디스크 공간과 대역폭,
시간이 충분한지 확인하세요. 오래된 블록을 버려 블록체인의 크기를 줄이도록 비트코인
코어를 설정할 수 있지만, 그래도 데이터셋 전체를 내려받기는 합니다.
====

이런 자원 요구에도 불구하고 수천 명이 비트코인 노드를 운영합니다. 어떤 사람은 라즈베리
파이(카드 한 팩 크기의 35달러짜리 컴퓨터)처럼 단순한 시스템에서 돌리기도 합니다.

[role="less_space pagebreak-before"]
노드를 운영할 이유가 무엇일까요? 가장 흔한 이유는 다음과 같습니다.

- 여러분이 받는 트랜잭션을 검증하는 데 제삼자에게 의존하고 싶지 않습니다.

- 어떤 트랜잭션이 여러분의 지갑에 속하는지 제삼자에게 알리고 싶지 않습니다.

- 비트코인 소프트웨어를 개발하고 있어서, 네트워크와 블록체인에 프로그래밍 방식(API)으로
  접근하기 위해 비트코인 노드가 필요합니다.

- 비트코인의 합의 규칙에 따라 트랜잭션을 검증해야 하는 애플리케이션을 만들고 있습니다.
  보통 비트코인 소프트웨어 회사는 노드를 여러 개 운영합니다.

- 비트코인을 지원하고 싶습니다. 여러분의 지갑이 받는 트랜잭션을 검증하는 데 쓰는 노드를
  운영하면 네트워크가 더 견고해집니다.

이 책을 읽고 있고 강력한 보안이나 뛰어난 프라이버시에 관심이 있거나 비트코인 소프트웨어를
개발한다면, 여러분 ((("Bitcoin Core", "nodes", "running", startref="bitcoin-core-nodes-running")))((("nodes", "running", startref="nodes-running")))((("running nodes", startref="running-nodes")))자신의 노드를 운영해야 합니다.

++alertnotify++:: 이 ((("alertnotify option (bitcoind option)")))노드의 소유자에게 긴급 경보를 보내도록 지정한 명령이나
스크립트를 실행합니다.

++conf++:: 설정 ((("conf option (bitcoind option)")))파일의 다른 위치를 지정합니다. 자기가 가리키는 설정 파일
안에는 넣을 수 없으므로, +bitcoind+ 의 명령줄 매개변수로만 의미가 있습니다.

++datadir++:: 블록체인((("datadir option (bitcoind option)"))) 데이터를 모두 넣을 디렉터리와 파일시스템을 고릅니다.
기본값은 홈 디렉터리의 _.bitcoin_ 하위 디렉터리입니다. 설정에 따라 이 글을 쓰는
시점에 약 10GB에서 거의 1TB까지 쓸 수 있으며, 최대 크기는 해마다 수백 기가바이트씩
늘어날 것으로 예상됩니다.

++prune++:: 오래된((("prune option (bitcoind option)"))) 블록을 삭제해 블록체인의 디스크 공간 요구량을 지정한
메가바이트 수로 줄입니다. 전체 블록체인을 담을 수 없는 자원 제약이 있는 노드에서
사용하세요. 시스템의 다른 부분은 현재 가지치기할 수 없는 디스크 공간을 쓰므로,
+datadir+ 옵션에서 언급한 최소 공간은 여전히 필요합니다.

++txindex++:: 모든 ((("txindex option (bitcoind option)")))트랜잭션의 인덱스를 유지합니다. 그러면 해당 트랜잭션이 담긴
블록이 가지치기되지 않은 한, 어떤 트랜잭션이든 ID로 프로그래밍 방식으로 가져올 수
있습니다.

[role="less_space pagebreak-before"]

고사양 하드웨어에서는 이 크기를 늘려 디스크 읽기·쓰기 횟수를 줄이고, 저사양
하드웨어에서는 디스크를 더 자주 쓰는 대신 메모리를 아끼도록 크기를 줄이세요.

++blocksonly++:: 미확인((("blocksonly option (bitcoind option)"))) 트랜잭션을 중계하는 대신 피어에게서 확인된 트랜잭션이 담긴
블록만 받아 대역폭 사용을 최소화합니다.

++maxmempool++:: 트랜잭션((("maxmempool option (bitcoind option)"))) 메모리 풀을 지정한 메가바이트 수로 제한합니다.
메모리 제약이 있는 노드에서 메모리 사용을 줄이는 데 쓰세요.

[[txindex]]
.트랜잭션 데이터베이스 인덱스와 txindex 옵션
****
기본적으로
비트코인 코어는((("txindex option (bitcoind option)")))((("transactions", "building complete index"))) 사용자 지갑과 관련된 트랜잭션 _만_ 담은 데이터베이스를
만듭니다. +getrawtransaction+ 같은 명령으로 _어떤_ 트랜잭션이든 접근할 수 있게 하려면
(<<exploring_and_decoding_transactions>> 참고) 비트코인 코어가 완전한 트랜잭션 인덱스를
만들도록 설정해야 하며, 이는 +txindex+ 옵션으로 할 수 있습니다. 비트코인 코어 설정
파일에 +txindex=1+ 을 넣으세요. 처음에 이 옵션을 설정하지 않았다가 나중에 전체 인덱싱으로
바꾸면, 인덱스를 다시 만들 때까지 기다려야 합니다.
****

동작하는 완전 인덱스 노드를 구성하는 예입니다.

==== 블록 살펴보기

블록을
살펴보는 ((("Bitcoin Core", "command-line interface", "exploring blocks", id="bitcoin-core-command-blocks")))((("command-line interface (Bitcoin Core)", "exploring blocks", id="command-blocks")))((("blocks", "exploring", id="blocks-explore")))((("exploring", "blocks", id="explore-blocks")))일은 트랜잭션을 살펴보는 것과 비슷합니다. 다만 블록은 블록
_높이_ 로도, 블록 _해시_ 로도 참조할 수 있습니다. 먼저 높이로 블록을 찾아봅시다.
블록 높이를 매개변수로 받아 그 블록의 _블록 헤더 해시_ 를 돌려주는 +getblockhash+
명령을 사용합니다.

==== 비트코인 코어의 프로그래밍 인터페이스 사용하기

+bitcoin-cli+ 도우미는 ((("Bitcoin Core", "command-line interface", "API access", id="bitcoin-core-command-api")))((("command-line interface (Bitcoin Core)", "API access", id="command-api")))((("API access", id="api")))비트코인 코어 API를 탐색하고 기능을 시험하는 데
아주 유용합니다. 하지만 API의 본래 목적은 기능에 프로그래밍 방식으로 접근하는 것입니다.
이 절에서는 다른 프로그램에서 비트코인 코어에 접근하는 방법을 보여줍니다.

비트코인 코어의 API는 JSON-RPC 인터페이스입니다. JSON은 사람과 프로그램 모두 쉽게 읽을
수 있게 데이터를 표현하는 아주 편리한 방법입니다. RPC는 원격 [.keep-together]#프로시저#
호출(remote procedure call)의 약자로, 네트워크 프로토콜을 통해 원격에 있는(비트코인 코어
노드에 있는) 프로시저(함수)를 호출한다는 뜻입니다. 여기서 네트워크 프로토콜은 HTTP입니다.

+bitcoin-cli+ 명령으로 어떤 명령의 도움말을 볼 때, 다재다능한 명령줄 HTTP 클라이언트인
+curl+ 로 이런 JSON-RPC 호출을 구성하는 예시가 함께 나왔습니다.

----
$ curl --user myusername --data-binary '{"jsonrpc": "1.0", "id":"curltest",
  "method": "getblockchaininfo", 
  "params": [] }' -H 'content-type: text/plain;' http://127.0.0.1:8332/
----

이 명령은 +curl+ 이 로컬 호스트(127.0.0.1)로 HTTP 요청을 보내 기본 비트코인 RPC
포트(8332)에 연결하고, +text/plain+ 인코딩으로 +getblockchaininfo+ 메서드에 대한
+jsonrpc+ 요청을 제출하는 모습을 보여줍니다.

+curl+ 이 요청과 함께 보낼 자격 증명을 요구한다는 점을 눈치챘을 것입니다. 비트코인
코어는 시작할 때마다 무작위 암호를 만들어 데이터 디렉터리에 +.cookie+ 라는 이름으로
넣어 둡니다. +bitcoin-cli+ 도우미는 데이터 디렉터리만 알면 이 암호 파일을 읽을 수
있습니다. 마찬가지로 <<cookie_auth>>에서 보듯 그 암호를 복사해 +curl+ 이나 (더 상위의
비트코인 코어 RPC 래퍼에) 넘길 수 ((("Bitcoin Core", "authentication")))((("authentication")))있습니다.
